GreenBasket documentation

Everything you need to install, customise and connect the template.

1. Template introduction

GreenBasket is a multi-page HTML template for supermarkets and daily grocery stores, built with Bootstrap 5.3, HTML5, CSS3 and vanilla JavaScript (ES6+). It includes two homepages, a full shop flow (listing → details → cart → checkout → confirmation → tracking), a customer account area and a separate admin panel with Chart.js analytics.

  • 34 ready pages · light & dark mode · RTL (Arabic / Hebrew) · WCAG 2.1 AA-minded markup
  • Cart, wishlist, shopping lists, addresses and demo orders persist in localStorage
  • No build step, no frameworks – open index.html and start editing
Important – front-end demo only. Authentication, live inventory, order processing, delivery tracking, payments, emails and the admin panel are simulated in the browser. Nothing is sent to a server and no money is charged. Before going live you must connect a backend/API (see sections 12–14). The UI states this clearly wherever a simulated action happens.

2. Installation

  1. Unzip supermarket-grocery-template.zip.
  2. Open index.html in a browser – everything works from the file system, but a local server is recommended (some browsers restrict localStorage on file://):
# any of these, from the template folder
npx serve .
python -m http.server 8080
# or use the VS Code "Live Server" extension

Upload the folder contents to any static host (Netlify, Vercel, GitHub Pages, cPanel / Hostinger shared hosting). Bootstrap, Bootstrap Icons, Chart.js and Google Fonts load from CDNs; product photos are hot-linked from Unsplash. To run fully offline, download those files into assets/vendor/ and assets/images/ and update the paths (see section 7).

Before publishing: replace https://www.example.com/ in every page’s canonical/OG tags, sitemap.xml and robots.txt with your domain (a project-wide find & replace works).

5. How to change the logo

The logo is an image (assets/images/logo-header.png, full version in logo.png); replace those files to rebrand. Search for class="brand" – it appears in the header, footer, auth pages and admin sidebar:

<a class="brand" href="index.html" aria-label="GreenBasket home">
  <img class="brand-logo" src="../assets/images/logo-header.png" alt="GreenBasket">
</a>

The favicon files (favicon.ico, favicon-16x16.png, favicon-32x32.png, apple-touch-icon.png) and the preloader (id="preloader", styled at the end of style.css) are in the same folder and every page.

6. How to change colours

All colours are CSS variables at the top of assets/css/style.css. Change them once and every page follows (Bootstrap buttons, forms and links are bridged to the same variables):

:root {
  --gb-primary: #218838;      /* brand green  */
  --gb-primary-dark: #1a6d2d; /* hover        */
  --gb-primary-text: #1e7b33; /* green text on light backgrounds (AA contrast) */
  --gb-secondary: #f4a62a;    /* warm orange  */
  --gb-accent: #e9f7ec;
  --gb-bg: #f8faf7;  --gb-surface: #ffffff;
  --gb-heading: #1b2b21;  --gb-text: #68756b;
  --gb-border: #e6ece6;   --gb-sale: #e5484d;
}

Dark-mode equivalents live in assets/css/dark-mode.css under [data-bs-theme="dark"]. When choosing new colours, keep text contrast at 4.5:1 or higher (white text on --gb-primary is 4.5:1 with the default green).

Fonts: change the Google Fonts link in each page’s <head> and the --gb-font-heading / --gb-font-body variables.

7. How to replace images

  • Page images (heroes, banners, blog, team) are regular <img> tags with Unsplash URLs – replace the src with your own file, e.g. assets/images/hero.jpg, and update the alt text.
  • Product & category images are set in assets/js/products.js (img field / U('photo-id') helper). Replace with your own URLs or paths.
  • Recommended sizes: hero 1400×1100, product 800×800 (square), category 500×375, blog 1200×750. Compress to WebP/JPEG under 200 KB.
  • If any image fails to load, it is automatically swapped for assets/images/placeholder.svg.

Unsplash photos are free to use under the Unsplash License. For a commercial store, use your own product photography.

8. How to edit text and content

Every page is plain HTML – open it in any editor and change the text. Sections are marked with comments such as <!-- 4. WEEKLY DEALS -->. The header and footer are repeated in each file; use your editor’s “Find in files” to update menu items, phone numbers or the address everywhere at once.

Prices written in HTML use data-price="499" (INR) so they convert when the visitor changes currency. Business details (phone, address, hours) also appear in the LocalBusiness JSON-LD in the <head> of Home, About, Contact and Delivery pages.

To translate for RTL languages, translate the text in the HTML files; layout mirroring is automatic.

9. How to manage products

Products and categories are defined in assets/js/products.js:

P('p01', 'Fresh Red Apples', 'fruits-vegetables', 'FarmLeaf', '1 kg',
  149, 180,          // price, original price (null = no discount)
  4.7, 214, 1820,    // rating, reviews, units sold (popularity)
  64,                // stock (0 = out of stock, <10 = "only X left")
  '1560806887-1e4cd0b6cbd6',  // Unsplash photo id (or use your own URL)
  { o: 1, e: 1 },    // flags: o = organic, e = essential, n = new
  'Crisp, juicy apples…',     // description
  KG)                // optional pack sizes [{label, mult}]

Homepage sections pick products automatically with data-product-grid="deals|best|essentials|organic|new|all", plus optional data-category and data-limit.

The admin Products page lets you add, edit and delete products; changes are saved in the browser and the demo shop uses them immediately (“Restore demo data” resets). In production, replace GB.getProducts() with data from your API (section 14).

10. How to configure dark mode

Dark mode uses Bootstrap 5.3’s data-bs-theme attribute on <html>. On first visit the OS preference (prefers-color-scheme) is used; the visitor’s choice is saved in localStorage (gb-theme) and applied before the page paints, so there is no flash.

// Force a theme from your own code
GB.setTheme('dark');   // or 'light'
// Default to light regardless of OS: in main.js change GB.getTheme to
GB.getTheme = () => GB.store.get('theme') || 'light';

Any element with data-theme-toggle becomes a toggle button. Adjust dark colours in dark-mode.css.

11. How to enable RTL

Choose العربية or עברית in the top-bar language selector (or the button in admin). The template then sets <html dir="rtl" lang="ar">, swaps Bootstrap to bootstrap.rtl.min.css and applies rtl.css. The choice is remembered.

To make a page RTL permanently (e.g. a fully Arabic site), set it in the HTML and point the Bootstrap link to the RTL file:

<html lang="ar" dir="rtl">
<link id="bootstrap-css" rel="stylesheet"
      href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.rtl.min.css" …>

Custom styles use logical properties (inset-inline-start, margin-inline-end), so most components mirror without extra rules.

12. How to connect contact & newsletter forms

All forms use data-validate (see validation.js) for accessible client-side validation. When a form is valid it fires a gb:valid event; demo handlers are at the bottom of validation.js. Replace the contact handler to send real messages, e.g. with Formspree:

contact(form) {
  fetch('https://formspree.io/f/YOUR_ID', {
    method: 'POST', body: new FormData(form), headers: { Accept: 'application/json' }
  }).then(r => r.ok ? showSuccess(form, 'Thanks! We will reply soon.')
                    : GB.toast('Could not send – please try again', 'error'));
}

Netlify Forms: add name="contact" data-netlify="true" to the form and remove the JS handler. Newsletter: post the email to Mailchimp/Brevo via your server (API keys must never be in front-end code). Always validate again on the server.

13. How to integrate payment gateways

The checkout shows Cash on Delivery, Card, UPI and Online Payment options with clearly marked placeholders. The integration point is the gb:valid handler in assets/js/cart.js (search for PAYMENT INTEGRATION POINT). A typical flow:

  1. Front end sends the cart and address to POST /api/orders.
  2. Your server re-prices the cart from the database (never trust client prices), creates the order and a payment session (Stripe PaymentIntent, PayPal order, Razorpay order).
  3. Front end opens the provider’s UI (Stripe Elements, PayPal Buttons, Razorpay Checkout / UPI intent).
  4. The provider calls your webhook; only then mark the order paid and redirect to order-confirmation.html?order=ID.
// Stripe example (after your server returns clientSecret)
const stripe = Stripe('pk_live_…');
const { error } = await stripe.confirmCardPayment(clientSecret, {
  payment_method: { card: cardElement, billing_details: { name } }
});

Replace the demo card inputs with the provider’s hosted fields so card data never touches your server (PCI-DSS).

14. How to connect backend APIs

All storage goes through a tiny wrapper (GB.store in main.js) and a few data functions, so swapping in an API is contained:

Demo function / keyReplace with
GB.getProducts() (products.js)GET /api/products, GET /api/products/:id
GB.cart / gb-cart (cart.js)/api/cart for logged-in users (keep localStorage for guests)
Checkout gb:valid → gb-ordersPOST /api/orders + payment (section 13)
GB.allOrders(), GB.findOrder() (dashboard.js)GET /api/me/orders, GET /api/orders/:id/tracking
Login / register handlers (validation.js)POST /api/auth/login, /register – use HTTP-only session cookies, never store passwords in the browser
Shopping lists, addresses, profile/api/me/lists, /api/me/addresses, /api/me
Admin (admin.js) gb-admin-* keysAdmin REST endpoints protected by server-side auth & roles
// Example (products.js): use live data instead of the demo array
fetch('/api/products')
  .then((r) => r.json())
  .then((list) => {
    GB.getProducts = () => list;  // every page now reads your catalogue
    GB.renderGrids();             // re-render homepage / related product grids
  });

Google Maps: replace the .map-placeholder blocks on Contact and Delivery pages with an embed iframe (Google Maps → Share → Embed a map) or the Maps JavaScript API.

Security checklist: protect /admin/ and /customer/ on the server, validate every input server-side, use HTTPS, add CSRF protection, and add Subresource Integrity (integrity) attributes to CDN links or self-host them.

15. Browser compatibility

Latest two versions of Chrome, Edge, Firefox, Safari (macOS & iOS) and Samsung Internet. Uses ES2018+, CSS custom properties, CSS grid and logical properties. Internet Explorer is not supported.

Tested at 375, 768, 1100 and 1440 px widths for horizontal overflow and JavaScript errors.
